# Purpose

This document defines the complete Dashboard experience for Atlas.

The Dashboard is not a traditional admin panel.

It is the user's travel command center.

Every element should help users understand:

• Where they are

• What comes next

• What requires attention

• How Atlas can help

The Dashboard should reduce cognitive load while keeping all important travel information within easy reach.

---

# Core Philosophy

Dashboard First.

Conversation First.

Timeline First.

The Dashboard revolves around the user's active journey rather than around menus or settings.

---

# Primary Goals

Allow users to continue planning immediately.

Provide clear travel progress.

Maintain conversation continuity.

Surface important recommendations.

Reduce navigation.

Increase confidence.

---

# Default Landing

After authentication Atlas opens:

Last AI Conversation

If no conversation exists:

Open Welcome Dashboard.

The user should never arrive at an empty page.

# AI Conversation Panel

The AI chat is the primary workspace.

Requirements:

Streaming responses

Conversation history

Suggested follow-up prompts

Message actions

Quick editing

Regeneration

Copy response

The Travel Timeline is permanently accessible.

It becomes the primary navigation for an active trip.

Timeline displays:

Past events

Current event

Upcoming events

Milestones

Transportation

Accommodation

Activities

Each event supports:

Hover (Desktop)

Bottom Sheet (Mobile)

Detailed contextual information

Current event remains visually highlighted.

# Personalization

Dashboard gradually adapts to user behavior.

Frequently used widgets become more prominent.

Unused widgets remain available but less emphasized.

Personalization never surprises the user.

---

# Multi-trip Support

Future versions support multiple active trips.

Users can switch trips without losing AI context.

Each trip preserves its own conversation and timeline.

---

# Offline Behaviour

If offline:

Dashboard remains usable.

Previously loaded itineraries remain accessible.

Timeline remains readable.

Changes sync automatically when connection returns.
