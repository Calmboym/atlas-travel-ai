# Purpose

This document defines the complete onboarding experience for Atlas.

The objective is not to teach the interface.

The objective is to build trust, reduce friction, and help the user create their first AI-generated trip as quickly as possible.

Success is measured by the user's first completed travel plan.

---

# Philosophy

The onboarding should feel like meeting an experienced travel companion.

Never like completing a registration form.

Atlas should ask only what is necessary.

Everything else is learned progressively.

---

# Primary Goals

Reduce cognitive load.

Demonstrate AI capabilities immediately.

Collect only essential preferences.

Reach first travel plan within minutes.

Create confidence in the product.

---

# User Types

Guest User

Authenticated User

Returning User

Each follows a slightly different flow.

---

# Guest Experience

Guests can immediately interact with Atlas.

No registration wall appears before value is demonstrated.

Guests may:

Generate itineraries

Chat with AI

Save travel plans locally

Edit plans

Use AI memory until the browser session ends

A sign-up prompt appears only when cloud synchronization or permanent storage is required.

---

# Authenticated Experience

Returning users skip onboarding.

Atlas restores:

Last conversation

Last trip

Preferences

Recent destinations

Theme

Language

Dashboard opens directly to the most recent AI conversation.

---

# First Impression

Within the first five seconds the interface should communicate:

Professional quality

Trustworthiness

Intelligence

Calmness

No aggressive marketing.

No popups.

No countdowns.

No forced actions.

---

# Landing CTA

Primary CTA:

Start Planning

Secondary CTA:

Explore Example Trips

The AI search box remains the main interaction point.

---

# Initial AI Prompt

The search field encourages natural language.

Examples:

"I want a 10-day trip to Japan in spring."

"Plan a family vacation in Italy."

"I have $2,000. Where should I go?"

Examples rotate subtly without distracting the user.

---

# Progressive Profile Collection

Atlas does not ask twenty questions at once.

Instead, preferences are gathered naturally during conversation.

Examples:

Budget

Travel style

Accommodation preference

Food preference

Transportation preference

Activity level

Accessibility requirements

Preferred languages

Family composition

Collected data updates the traveler profile automatically.

---

# First AI Response

The first response must arrive quickly.

Streaming begins immediately.

The AI should acknowledge the request before generating the full itinerary.

Example behavior:

Understanding request

↓

Collecting destination knowledge

↓

Planning itinerary

↓

Building timeline

↓

Preparing recommendations

This reassures the user that work is in progress.

---

# Itinerary Preview

Before asking for confirmation, Atlas presents:

Trip summary

Estimated budget

Duration

Key destinations

Travel style

Highlights

Users can refine the plan through conversation.

---

# Confirmation Step

Once satisfied, users confirm the itinerary.

Confirmation creates:

Trip record

Travel timeline

Dashboard entry

Calendar-ready schedule

AI memory context

---

# Travel Timeline Introduction

Immediately after confirmation, Atlas displays the interactive travel timeline.

The timeline becomes the central navigation for the trip.

It always answers:

Where am I now?

What comes next?

What have I already completed?

Users can inspect every event for detailed information.

---

# Empty Dashboard

First-time users see:

Welcome message

Suggested prompts

Popular destinations

Example trips

Recent AI capabilities

Never an empty screen.

---

# Sign-Up Timing

Registration is requested only when users attempt actions requiring cloud persistence, such as:

Saving across devices

Sharing trips

Notifications

Future bookings

The request clearly explains the benefit.

---

# Returning Users

Returning users are greeted by name (if available).

Atlas restores context automatically.

The user should never feel that previous work was lost.

---

# Personalization

As conversations continue, Atlas gradually adapts:

Recommendations

Suggested destinations

Budget assumptions

Conversation tone

Travel insights

Without overwhelming the user.

---

# Accessibility

Every onboarding step supports:

Keyboard navigation

Screen readers

Reduced motion

RTL layouts

Large touch targets

Localization

---

# Performance

The onboarding experience must remain lightweight.

Hero animations load progressively.

Interactive elements become usable immediately.

AI responses begin streaming without waiting for the complete result.

---

# Success Metrics

Successful onboarding means:

User starts a conversation

AI generates an itinerary

User refines the itinerary

User confirms the trip

Travel Timeline is created

User reaches the dashboard

---

# Definition of Done

The onboarding experience is complete only if:

✓ First value delivered within minutes

✓ Guest flow fully supported

✓ Registration never blocks exploration

✓ AI conversation feels natural

✓ Timeline created after confirmation

✓ Dashboard populated automatically

✓ Accessible

✓ Responsive

✓ Theme compatible

✓ Performance budget satisfied
